## 🧠 方案背景

互联网大厂（如腾讯、华为）已将攻击面管理从"定期渗透"升级为 **7x24小时持续对抗**。

本方案结合 **CTEM（持续威胁暴露管理）** 框架与国内常见合规要求（如"两高一弱"整治），提供一套**可落地、分阶段、低成本启动**的资产暴露面治理体系。

### 适用场景

- ✅ 不清楚企业有多少未知资产/影子资产
- ✅ 漏洞太多修不完，无法判断优先级
- ✅ 暴露面（公网IP、代码泄漏、云存储）缺乏持续监控
- ✅ 安全运营依赖人工，希望建立自动化闭环



## 🎯 核心思路

| 阶段 | 核心原则 | 关键转变 |
|--|--|--|
| 基础治理 | **先看见，再保护** | 从"扫漏"到"清资" |
| 主动防御 | **以攻击者视角持续验证** | 从"定期报告"到"实时风险仪表盘" |
| 闭环运营 | **风险必须处置，处置必须量化** | 从"安全团队背锅"到"责任人考核" |
| **贯穿始终** | **自动化优先，人工只做决策与验证** | 从"人海战术"到"AI提效" |



## 🗺️ 三阶段实施路线

### 第一阶段：基础治理（1-2个月）

**目标**：消除未知资产，建立统一资产台账。

| 工作项 | 具体措施 | 开源/免费工具推荐 |
|--|-|--|
| 多源资产发现 | 主动扫描+流量解析+云API拉取+EDR日志 | `Nmap`, `Masscan`, `Zeek`, 云厂商API |
| 资产归属标定 | 对接CMDB，人工认领未标记资产 | `Jira` (免费版), 自建轻量资产表 |
| 暴露面收敛 | 关闭非必要端口/公网IP，下线老旧测试域名 | 云安全组策略审计（`AWS Trusted Advisor`社区版） |
| 建立资产台账 | 输出动态更新的资产清单（IP/域名/端口/组件/负责人/最后活跃时间） | `CSV+Python`脚本, 或开源CMDB（`iTop`, `GLPI`） |

> **验收标准**：核心资产覆盖率≥99%，无主资产占比＜3%



### 第二阶段：主动防御（2-3个月）

**目标**：自动化发现风险，精准定级高危漏洞。

| 工作项 | 具体措施 | 开源/免费工具推荐 |
|--||--|
| 外部暴露面监控(EASM) | 监控公网端口、云存储桶、代码仓库泄漏、过期证书 | `Shodan`(小企业版), `TruffleHog`, `GitGuardian`(免费层) |
| 漏洞与配置扫描 | 每周围内网/云资产扫描+基线合规检查（如CIS Benchmark） | `OpenVAS`, `Grype`(容器), `Clair` |
| 优先级排序(VPT) | 结合CVSS、资产重要性、在野利用情报计算风险分 | `DefectDojo` + 自研权重脚本 |
| 自动化验证(可选进阶) | 对高危漏洞进行无害化POC验证 | `Metasploit`(谨慎), 自研Python POC |

> **验收标准**：高危漏洞发现→确认≤24h，误报率≤10%



### 第三阶段：闭环运营（持续）

**目标**：风险处置自动化，修复时效量化考核。

| 工作项 | 具体措施 | 开源/免费工具推荐 |
|--|--||
| 自动化处置 | 对未授权Redis等服务自动触发WAF/防火墙封禁，自动吊销泄漏密钥 | `TheHive`+`Cortex`, 云厂商函数计算自研联动脚本 |
| 工单派发与跟踪 | 生成修复工单→指派责任人→跟踪状态→催办 | `Jira`, 飞书/钉钉机器人+表单 |
| 修复时效考核(MTTR) | 高风险24h封禁/修复，中风险7d，低风险30d，纳入绩效 | 自建Dashboard (`Superset`, `Grafana`) |
| 持续度量与报告 | 每月输出报告：覆盖率、风险趋势、修复率、MTTR达标率、TOP未修复风险 | `Metabase`, `Excel`+脚本 |

> **验收标准**：高风险24h修复率≥80%，MTTR≤5天

## ⚠️ 落地风险应对

| 风险场景 | 应对措施 |
|-|--|
| 业务部门不配合修复 | 安全考核扣分；安全团队提供"一键修复脚本"；高风险漏洞可直接封禁 |
| 扫描影响业务稳定性 | 设置扫描窗口(凌晨)；核心系统降低并发或仅用流量分析 |
| 告警太多，分析不过来 | VPT只关注TOP20；维护误报库自动过滤；SOAR剧本自动处理 |
| 预算有限 | 优先第一阶段+第二阶段的免费工具；用人工+表单代替SOAR |



## 🚀 快速开始（MVP版）

若你想**1天内跑通最小闭环**，可执行以下步骤：

1. **资产发现**

```bash
nmap -sS -p 1-1000 -iL ip_list.txt -oA quick_scan
```

2. **漏洞扫描**

```bash
# 使用OpenVAS的CLI
gvm-cli --gmp-username admin --gmp-password pass socket --socketpath /var/run/gvmd.sock --xml "..."
```

3. **暴露面检查**

```bash
# 检查代码仓库泄漏的密钥
trufflehog --regex --entropy=False https://github.com/yourorg/repo.git
```

4. **工单派发（飞书机器人示例）**

```python
import requests

webhook = "https://open.feishu.cn/open-apis/bot/v2/hook/xxx"
data = {"msg_type": "text", "content": {"text": "请修复高危漏洞：... 责任人：@all"}}
requests.post(webhook, json=data)
```

5. **查看结果**

将扫描结果导入 `DefectDojo` 或 Excel，筛选出优先级最高的5个漏洞，开始修复跟踪。

> 📌 一个完整的MVP脚本示例（`quick_start.sh`）可在 [`/demo`](./demo) 目录中找到。
